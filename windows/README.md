# Kanki VPN برای ویندوز

کلاینت ویندوزی کانکی: همان اشتراک پنل (`/sub/<کد>`)، همان سرورها، با معماری استاندارد ویندوز.

## معماری

```
 KankiVPN.exe  (WPF، کاربر عادی، بدون ادمین)
      │   JSON خط‌به‌خط روی \\.\pipe\KankiVPN
      ▼
 kanki-svc.exe (Windows Service، SYSTEM)
   ├─ core      اشتراک، تنظیمات، اتصال، نگهبان اتصال، اتصال دوباره
   ├─ tunnel    Wintun + amneziawg-go (WireGuard / AmneziaWG)، آدرس، مسیرها، DNS
   └─ firewall  WFP: کیل سوییچ، جلوگیری از نشت DNS و IPv6، تقسیم ترافیک
```

| معیار | چطور |
|---|---|
| ۱. پروتکل استاندارد | WireGuard (ChaCha20-Poly1305، Curve25519، BLAKE2s) با `amneziawg-go`. همان موتور AmneziaWG را هم اجرا می‌کند (کلیدهای `Jc`، `S1…S4`، `H1…H4`، `I1…I5`؛ نسخه‌ی ۲). بدون این کلیدها = WireGuard خالص. |
| ۲. کارت شبکه‌ی مجازی | Wintun (درایور امضاشده‌ی WireGuard) با GUID ثابت تا ویندوز هر بار «Kanki VPN 2، 3…» نسازد. |
| ۳. مسیریابی و WFP | مسیرها = AllowedIPs منهای «بیرون تونل» (آدرس خود سرور، LAN، رنج‌های استثنا)؛ ویندوز طولانی‌ترین پیشوند را برمی‌دارد، پس حلقه‌ی مسیر و نیاز به پاییدن مسیر پیش‌فرض نیست. کیل سوییچ با WFP: همه بسته، جز تونل، بسته‌های خود سرویس، loopback، DHCP، NDP و رنج‌های مجاز. تقسیم ترافیک: «همه»، «همه به‌جز…»، «فقط…» (بر اساس IP/رنج). |
| ۴. زبان | هسته و درایور: Go. رابط: C# / WPF (.NET 8، تک‌فایل). |
| ۵. امنیت | DNS فقط به سرورهای DNS تونل (WFP پورت ۵۳ بقیه را می‌بندد؛ سرورهای DNS همیشه از تونل می‌روند، حتی اگر در رنج استثنا باشند). IPv6: اگر تونل IPv6 ندارد، IPv6 بیرون تونل بسته است. رمزنگاری: ChaCha20-Poly1305 (استاندارد WireGuard). |
| ۶. سرویس جدا | سرویس SYSTEM کارت شبکه، مسیر و فایروال را دارد؛ برنامه فقط از راه پایپ دستور می‌دهد. پایپ: SYSTEM و Admin کامل، کاربر واردشده خواندن/نوشتن، شبکه ممنوع. برنامه قبل از اولین درخواست چک می‌کند آن طرف پایپ واقعاً `kanki-svc.exe` کنار خودش است. |

### رفتارهای مهم
- **کیل سوییچ واقعی:** اگر سرور جواب ندهد (بدون handshake ۴۰ ثانیه اول یا ۳ دقیقه بعد)، تونل از نو ساخته می‌شود و در
  این فاصله اینترنت بسته می‌ماند. اگر وصل نشود، هر ۱۰ ثانیه دوباره و همچنان بسته. فقط «قطع کن» باز می‌کند.
- **عوض کردن قانون‌ها بدون نشت:** قانون‌های تازه‌ی WFP اول نصب می‌شوند، بعد قبلی‌ها برداشته می‌شوند.
- **سرویس هیچ‌وقت کامپیوتر را بی‌اینترنت رها نمی‌کند:** همه‌ی قانون‌ها در session پویای WFP هستند؛ اگر سرویس بمیرد
  قانون‌ها هم می‌روند. ویندوز سرویس را دوباره روشن می‌کند (Recovery) و سرویس دوباره وصل می‌شود.
- **بعد از ریستارت:** اگر VPN روشن بود (یا «وصل شدن با روشن شدن ویندوز»)، سرویس خودش وصل می‌شود.
- **هیچ اسکریپتی اجرا نمی‌شود:** کانفیگی که `PreUp/PostUp/...` دارد رد می‌شود.
- **راز‌ها در سرویس می‌مانند:** لینک کانفیگ‌ها (کلید خصوصی دارند) و کد اشتراک هیچ‌وقت به برنامه فرستاده نمی‌شوند.
  فایل وضعیت در `%ProgramData%\KankiVPN` فقط برای SYSTEM و Administrators قابل خواندن است.
- **وقتی پنل یا DNS در دسترس نیست:** آخرین کانفیگ و آخرین آدرس سالم سرور استفاده می‌شود. DNS سرویس از خود پروسه
  فرستاده می‌شود (نه سرویس DNS ویندوز) تا پشت کیل سوییچ هم کار کند.

### چیزهایی که این نسخه ندارد
- **تقسیم ترافیک بر اساس برنامه** (مثلاً «تلگرام بیرون از VPN»): در ویندوز بدون درایور کرنل امضاشده (WFP callout)
  شدنی نیست؛ این نسخه بر اساس IP/رنج است.
- KANKI MIX، microtun، Hysteria2 و Xray: فعلاً فقط WireGuard و AmneziaWG. هسته‌های Go آن‌ها (`kmix-core`، `mtun-core`)
  بعداً می‌توانند پشت همین Wintun بیایند.
- OpenVPN و IKEv2: پنل کانفیگ OpenVPN می‌دهد ولی برنامه‌ی ویندوز فعلاً آن را نشان نمی‌دهد.
- امضای کد (Authenticode): فایل نصبی امضا ندارد، پس SmartScreen هشدار می‌دهد. برای انتشار عمومی گواهی امضا لازم است.

## پوشه‌ها
| کار | فایل |
|---|---|
| شروع سرویس، install/uninstall/debug | `service/cmd/kanki-svc/main_windows.go` |
| خواندن کانفیگ WG/AWG و ساختن UAPI | `service/internal/conf/` |
| مسیرها و تقسیم ترافیک | `service/internal/route/` |
| خواندن اشتراک پنل (مثل `SubscriptionApi.kt`) | `service/internal/sub/` |
| مدیریت اتصال، کیل سوییچ هنگام اتصال دوباره | `service/internal/core/` |
| پروتکل پایپ | `service/internal/ipc/` |
| تنظیمات و فایل وضعیت | `service/internal/state/` |
| WFP (برگرفته از WireGuard for Windows، MIT) | `service/internal/firewall/` (`blocker.go` بازنویسی ما) |
| Wintun، آدرس، مسیر، DNS | `service/internal/tunnel/` |
| برنامه (WPF) | `ui/KankiVPN/` (`MainWindow.xaml`، `PipeClient.cs`، ترجمه در `Strings.cs`) |
| فایل نصبی (Inno Setup) و تست نصب | `installer/` |

## ساخت و تست
- `cd windows/service && go test -race ./...` (روی لینوکس هم). `GOOS=windows go vet ./...` برای بخش ویندوز.
- CI (`.github/workflows/windows.yml`): تست روی لینوکس، بعد روی ویندوز: ساخت سرویس، تست واقعی کارت شبکه / مسیر / DNS /
  WFP با دسترسی ادمین، ساخت برنامه، عکس صفحه‌ها (`KankiVPN.exe --shot <پوشه>`)، نصب سرویس و گفت‌وگو از راه پایپ،
  و ساخت `KankiVPN-Setup-x.y.z.exe`. خروجی‌ها در Artifacts همان اجرا.
- اجرای دستی روی ویندوز (ادمین): `kanki-svc.exe debug` در یک ترمینال، بعد `KankiVPN.exe`.
